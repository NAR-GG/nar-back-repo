# 인프라

프로덕션 전부가 집 맥미니(M1 16GB) 위 k3s 에 있다. **EC2 는 2026-08-19 종료했다.**
AWS 비용이 0 이 됐고, 그 대가로 집 회선과 기계 한 대가 단일 실패점이 됐다.

이 파일은 **색인**이다. 내용은 각 하위 문서에 있고, 여기는 "어디를 보면 되는지"와
"어떻게 여기까지 왔는지"만 적는다.

## 어디를 보면 되나

| 문서 | 무엇이 있나 | 언제 여기를 보나 |
|---|---|---|
| [`macmini/`](macmini/README.md) | 호스트 설정 원본, 감시 두 겹, 포트, 단일 실패점(호스트↔VM 포워딩), 배포 함정 3개 | 서버가 이상할 때, 배포가 조용히 실패했을 때 |
| [`k8s/`](k8s/README.md) | **실제 적용되는** k3s 선언. ArgoCD 가 이 디렉토리를 본다. 파드·라우팅·봉인 시크릿·리소스 근거 | 파드를 만지거나 시크릿을 바꿀 때 |
| [`argocd/`](argocd/README.md) | 부트스트랩 순서, `deploy` 브랜치 규약, "Synced" 가 뜻하지 않는 것 | 클러스터를 새로 세울 때, 롤백할 때 |
| [`monitoring/`](monitoring/README.md) | Prometheus·Loki·Grafana 원본, 대시보드 규약, 자주 쓰는 PromQL·LogQL | 지표가 안 보일 때, 장애 조사할 때 |
| [`../docs/macmini-home-server-setup.md`](../docs/macmini-home-server-setup.md) | 기기 구입·검수, 헤드리스 macOS 설정, 밟은 함정 4개 (2026-08-13 시점 기록) | 기계를 새로 세울 때 |
| [`../docs/adr/`](../docs/adr/) | 되돌리기 어려운 결정의 근거 | "왜 이렇게 했지" 싶을 때 |

`macmini/` 와 `k8s/` 의 차이가 헷갈리기 쉽다. `macmini/` 는 **보관용 사본**(서버에서 손으로 바꾼 것을
따라 적는 곳)이고, `k8s/` 는 **소스**(여기를 바꾸면 클러스터가 따라온다)다.

## 지금 구조

```
사용자
  │
  ▼  Cloudflare 엣지 (TLS 종단)
cloudflared 파드 ──> Traefik ──> nar-web 파드          ┐
                                                        ├──> 맥미니 MySQL 8.4 :3306
                    nar-scheduler 파드 (replicas 1) ────┘        (macOS 호스트)

관측:  두 파드 ──pull──> Prometheus ─┐
       Alloy    ──push──> Loki ──────┼──> Grafana (grafana.nar.kr)
       춘천 박스 ────────────────────┘     Uptime Kuma (kuma.nar.kr)
```

- 터널까지 클러스터 안이라 **요청 경로가 호스트↔VM 경계를 안 건넌다** (#446)
- `nar-web` 과 `nar-scheduler` 는 **같은 이미지**고 `APP_SCHEDULING_ENABLED` 로만 역할이 갈린다 (#442)
- 스케줄러는 **언제나 정확히 하나**다. 중복 실행 가드가 없다

## 그때 계획 vs 실제

`docs/macmini-home-server-setup.md` 의 「다음 단계」는 2026-08-13 에 쓴 것이다.
그 문서는 **일부러 그대로 둔다** — 예측이 틀린 지점이 이 이전의 교훈이라서다.

| 08-13 의 계획 | 실제 |
|---|---|
| ① self-hosted runner 부터 (리스크 없는 순이익) | **안 했다.** 무료 러너를 그대로 쓴다 |
| ② Prometheus·Grafana | 했다 (08-15). 순서만 ①을 건너뛰었다 |
| ③ 스테이징을 2~3주 굴려 집 회선을 실측 | **안 했다.** 구입 08-13 → 컷오버 08-17, 나흘 |
| ④ EC2 를 한 달 병행한 뒤 해지 | **이틀이었다.** 배포 전환 08-17 18:37 → 은퇴 08-19 22:49 |
| "단일 노드 k8s 는 스케줄링·HA 가 무의미하므로 학습 목적이 아니면 얹을 이유도 없다" | **얹었다** (08-18, #416~#422). 근거는 [ADR 0001](../docs/adr/0001-single-node-k3s.md) |
| 메모리 예산에 Elasticsearch 2.5GB | **은퇴시켰다** (#449, #451, #452). 색인이 늘 0건이라 검색은 처음부터 MySQL 경로만 돌고 있었다 |

읽는 방법: 계획이 틀린 게 문제가 아니라, **틀렸다는 걸 언제 알았는지**가 기록의 값이다.
③④가 빨라진 건 ②(관측)를 먼저 해서 "지금 정상인가"를 30초에 판단할 수 있었기 때문이다.

| 항목 | 상태 |
|---|---|
