어디에 붙일까

추천: 안 1 (챔피언 픽 탭 하단)
· 픽 = "누가 뭘 골랐나", 스코어보드 = "그래서 어떻게 됐나". 같은 질문의 연속이라 한 화면에서 스크롤로 이어짐
· 탭 개수 그대로. 390px에 탭 4개 넣으면 한글 라벨이 깨진다
· API 추가 0 — 픽 탭이 이미 부르는 /champions 응답에 필드만 붙이면 됨. 안 2는 /events를 보는 탭이라 스코어보드용 호출이 따로 붙는다

안 2가 나은 경우 — 라이브 중 "지금 상황판"으로 쓰게 할 거면. 타임라인 ↔ 스코어보드를 칩으로 오가는 게 자연스럽다. 대신 종료된 경기에서 "라이브 이벤트 > 스코어보드"는 이름이 어색하다.

안 한 것 — 4번째 최상위 탭. 폭도 문제고, 픽/스코어보드가 따로 놀면 세트 드롭다운을 두 번 만지게 된다.

팀 요약

골드 차이·총킬은 참가자 행 합산이라 새 저장이 필요 없다. 오브젝트는 live_game_object_event에 이미 쌓이는 중 — DRAGON(6종 + elder) · BARON · TOWER · INHIBITOR · KILL, 각각 value_after에 팀 누적 수치가 들어있다.

피드에 없는 것 — 전령·유충·아타칸. 이벤트 타입 자체가 안 내려온다.

행 구성

op.gg 모바일과 같은 순서. 390px에서 실측으로 들어간다:
챔피언34 + 룬15 + 이름80 + KDA56 + 아이템 8×17 = 359 / 366

· 아이템 8칸 = 코어 7 + 장신구. 2026 퀘스트로 원딜·서포터가 7개를 들기 때문 (원딜 최종분 24%가 실제로 7개)
· 룬은 핵심룬 + 부트리 아이콘 2개까지만. 나머지는 시트에서
· KDA 아래 킬관여, 이름 아래 CS·골드 — 두 줄로 나눠야 폭이 산다

데이터는 프로덕션 nardb 실값 (GEN 2:0 T1, 세트별 마지막 분 스냅샷 22831 / 22932). 아이콘은 ddragon 16.16.1.
